# Polaris Launch Readiness

Last updated: 2026-07-26

This is a living business and product checklist. It is not legal or tax advice.
Items with legal, tax, or regulatory consequences require qualified professional
review before Doug relies on them.

## Before an external private alpha

### Product and operations

- [x] The hosted alpha has separate user accounts and observatory data isolation.
- [ ] Onboarding gets a new user to a credible nightly recommendation.
- [ ] The recommendation explains the important reasons without exposing internal scoring recipes.
- [x] Tenant export and a disposable restore rehearsal have passed.
- [ ] A dated hosted export is retained on encrypted off-device media.
- [ ] A full restore into a separate Supabase project has passed.
- [ ] Feedback, support contact, and error monitoring are tested.
- [ ] A narrow alpha invitation and an acceptance/support process are ready.

### Brand and communication

- [ ] A provisional public name has passed the preliminary finalist screen.
- [ ] A suitable domain is registered only after that preliminary screen.
- [ ] A simple landing page accurately explains the alpha, the problem it solves, and how to request access.
- [ ] Screenshots, basic help, and a feedback form use the same plain language as the product.

### Legal and privacy review

- [ ] A qualified attorney has reviewed the intended privacy, terms, user-data, and branding/trademark approach as appropriate for the release.
- [ ] Data collection, retention, deletion, and support-access practices are documented.
- [ ] Source code remains in a private repository with controlled access and verified backups.

## Before a larger closed beta

- [ ] Alpha evidence shows users return to Polaris for real observing decisions.
- [ ] The highest-severity onboarding, privacy, reliability, and comprehension issues are resolved.
- [ ] Basic activation, repeat-use, and support metrics are defined and observed.
- [ ] Cost alerts and a monthly operating-cost review are in place.
- [ ] The beta scope, feedback cadence, and stop/continue criteria are written down.

## Before public launch

- [ ] A launch decision is supported by beta behavior, not compliments or feature count.
- [ ] The public name and key brand assets have received the appropriate professional review.
- [ ] Privacy, terms, support, billing, and data-deletion practices are ready for the chosen market.
- [ ] Documentation, onboarding, screenshots, marketing site, and store assets are complete for the channels actually being launched.
- [ ] The first post-launch support and release plan is ready.
